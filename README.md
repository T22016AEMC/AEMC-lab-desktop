# AEMC Lab Desktop

macOS 風格的虛擬桌面網頁，桌面是一座寵物養殖場，用來集中開啟部署在網路上的小程式（GitHub Pages / Render）並內建小遊戲。純前端，部署到 GitHub Pages。

正式網址：https://t22016aemc.github.io/AEMC-lab-desktop/

## 功能

- 開機畫面，點擊後直接進入桌面（不需要全螢幕）
- 頂部選單列（Logo →「關於這個桌面」、啟動台小圖示、遊戲館小圖示、作用中程式名稱、寵物數量與金幣、「建築」按鈕、日期時間）
- 桌面是像素風的寵物養殖場（見下方），畫面貼合瀏覽器可視區域（扣掉選單列），視窗縮放時即時重新計算；啟動台的入口是場景裡的住家（點門），備用入口是選單列小圖示與 F4；底部 Dock 平時隱藏，有內建視窗（小遊戲）開啟時才滑出；鐘塔的門是遊戲館的入口（滑鼠移到門上換成開門版，點門開啟「遊戲館」視窗）
- 視窗系統（只給內建程式使用）：紅黃綠按鈕、拖曳、邊緣與角落縮放、雙擊標題列最大化、最小化動畫、置頂、同一程式只開一個視窗
- 外部程式一律用瀏覽器新分頁開啟；啟動台是使用者自己的程式清單，可新增、編輯（右鍵）、刪除（右鍵、需確認）、恢復預設程式，清單存在瀏覽器
- 電腦專用：可視寬度低於 1024px 時只顯示「本網站僅支援電腦瀏覽，請使用電腦開啟」，不載入桌面與養殖場
- 5 個內建小遊戲（踩地雷、2048、貪食蛇、彈珠台、飛機打怪），只放在「遊戲館」（鐘塔的門，備用入口是選單列的遊戲館小圖示），不在啟動台
- PWA：可安裝成電腦的獨立視窗（`display: standalone`）

## 本機啟動

需要 Node.js 20.19 以上（建議 22）。

```bash
npm install
npm run dev        # 開發模式，網址 http://localhost:5173/
```

預覽正式建置的結果：

```bash
npm run build
npm run preview    # 網址 http://localhost:4173/
```

## 寵物養殖場（桌面）

桌面本身就是一個像素風的寵物養殖場：橫向草地，左下是住家、右邊是路燈、最右側後排是鐘樓、住家右上方後排是水池，中間有 2 棵樹與少量固定的裝飾，天空隨日夜與天氣變化。**住家就是啟動台的入口**：滑鼠移到門上會開門、門牌發亮，點門開啟啟動台（備用入口：選單列的小圖示、快捷鍵 F4）。程式碼在 `src/farm/`。

**場景**
- 以像素素材繪製（Canvas 2D）。邏輯畫面約 480×270，用整數倍放大（`image-rendering: pixelated`，已處理 devicePixelRatio，不會模糊）；視窗更寬時天空與草地向左右延伸、不變形，底部貼地。層次由後到前：天空漸層 → 太陽／月亮 → 星星 → 雲 → 遠景 → 草地 → 後排物件（鐘樓、樹）→ 小路 → 前排物件與寵物（依腳底 y 排前後）。配置固定：住家在左下、路燈在住家右邊、水池在住家正上方（靠左、整個素材在草地上緣以下）、兩棵樹與鐘樓的腳底貼近草地上緣（後排成一排）、蘑菇與樹樁等裝飾也在這一排（腳底與樹同一條線，草地中段整片空出來）。預留的建築空位（本版不顯示）：狗窩、食盆水盆、貓跳台站在沙地走道的上半部，野餐墊、遊樂設施、營火、花圃、沙坑在草地（左邊那棵樹的左側，水面 2 幀閃動）、鐘樓在最右側後排（周圍約 1.5 倍鐘樓寬度不放裝飾）、2 棵樹在中間偏左與偏右、裝飾物（灌木、蘑菇、石頭、小花叢）散布在小路兩側；視窗太窄時自動少放樹與裝飾。寵物不會走進住家、不會停在燈柱後面，鐘樓與水池前方可以走，水池（含石頭）、樹幹、鐘樓底座不可站。
- 日夜依本機實際時間（清晨 5–8、白天 8–17、黃昏 17–19:30、夜晚 19:30–5），天空顏色平滑過渡；夜晚加暗色疊層、住家亮燈、路燈發光、有星星與月亮。鐘樓的時鐘完全由程式畫（直徑約 48 的金框奶油色鐘面、12 個刻度、3／6／9／12 較粗），時間取自遊戲的時間來源（測試模式改時間時鐘面跟著變）：分針 = 分鐘×6（含秒的連續值）、時針 = (時%12)×30 + 分鐘×0.5，皆從 12 點鐘方向順時針量；夜晚鐘面不加暗，維持清楚可讀（`pixel/clock.ts`，有純函式測試：12:00、3:00、6:00、9:00、14:30、23:45、0:15）。
- 陸地寵物的睡覺時間是本機時間 23:00～隔天 6:00（`balance.ts` 的 `sleep`），與天空的日夜變化分開；黃昏與 23:00 前仍醒著正常活動。
- 天氣（晴、多雲、下雨、下雪）每 4 小時換一次，以時間為種子，重新整理不會跳變；純視覺效果，不連網。下雨是細長的淺藍色短線（1～2 像素寬、4～8 像素長）、下雪是小雪花素材、密度適中，不影響看寵物與選單。
- 固定的場景物件與位置在 `src/farm/pixel/layout.ts`（`sceneObjects`）；日後放其他建築的空位在 `buildingSlots`（本版不顯示）。

**寵物**
- 狗 6 個品種（柴犬、柯基、哈士奇、黃金獵犬、邊牧、貴賓）、貓 6 種花色／品種（橘虎斑、黑貓、三花、暹羅、英短藍貓、布偶貓），貓狗合計最多 6 隻，每隻領養 15／25／35 金幣，第一隻免費。領養視窗用「大家的正面照」像素圖當預覽。
- 每種動物只有一個外觀（不做胖瘦、幼年外觀）。體重、身高係數、「領養滿 3 天成年」只是數值，顯示在資訊裡。飽食度／心情／清潔度（0～100）隨時間緩慢下降；離開網站期間依經過時間補算，但最低不低於 20。
- 動作用像素幀播放：走路（walk_a／walk_b 交替）、待機（stand）、坐下、睡覺、吃東西、開心、梳毛；往左走水平翻轉，不旋轉、不縮放。行為邏輯（`pixel/pets.ts`）只決定「動作名稱」，名稱到幀的對應在 `ANIMS` 表，之後加玩耍動作只要新增名稱與幀。
- 頭上的狀態圖示：餓＝驚嘆號、心情低＝汗滴、髒＝泡泡、睡覺＝ZZZ、開心＝愛心。

**操作**
- 點寵物，頭上彈出氣泡選單：名字、三條像素風小條（飽食、心情、清潔）與所有操作（每次 1 金幣）：餵食、撫摸、洗澡、散步（狗）、梳毛（貓）、叫醒（睡覺中）。點空白處關閉。「洗澡」會讓寵物自己走到水池前再跳進去（見下方「拖曳與水池洗澡」）。睡覺時：撫摸可用（不會醒來，心情 +5）；叫醒可用（貓醒來不開心心情 −15，狗醒來很開心心情不變）；其他顯示「正在睡覺，可以先叫醒」。若仍在睡覺時間內，約 10 分鐘沒有任何互動就會自己回去睡。
- 滑鼠移到寵物身上：牠會看向滑鼠並輕輕跳一下。
- 選單列右側「＋領養」按鈕，旁邊依序是「建築」按鈕、寵物數量（例如 3/6）與金幣；畫面左下不放任何浮動按鈕。寵物之間有分散機制（互相避讓、草地與小路都會去），六隻同場時重疊比例很低。
- 金幣（內部欄位仍叫 `points`）：新存檔初始 50（已有存檔保留自己的數量）；每日第一次開啟 +5（以本機日期判斷）；心情高於 70 的寵物每天最多 4 次叼來禮物，點擊領取 +1～3 金幣；日常操作每次 −1。另外可以賺金幣（見下方「金幣經濟」）。

### 像素素材與處理管線

遊戲用的像素素材在 `public/assets/`（圖集 PNG ＋ `manifest.json`：每張的位置、尺寸、錨點、動畫幀順序）。原圖是 AI 生成的洋紅底像素風圖，放在 repo 外的資料夾（預設是 repo 上一層的「像素風圖片」，已加進 `.gitignore`，不進 repo）。要重新產生素材：

```bash
node scripts/process-assets.mjs "<原圖資料夾>"      # 或設定環境變數 ASSET_SRC
```

腳本會：① 去背（洋紅底、細白框、格線；alpha 只有 0 或 255）② 依檔案的欄×列切成單張，錨點 = 水平中心＋腳底基準線（同一隻動物各姿勢腳底對齊）③ 還原真像素：估算原圖的像素格大小，以最近鄰重新取樣成 1 格 = 1 像素，狗與貓共用同一個像素格大小，所有素材像素密度一致 ④ 把遠景、小路左右鏡像拼成可水平重複，草地方塊以 2×2 鏡像拼成可上下左右無縫 ⑤ 打包圖集、產生 manifest、處理報告 `screenshots/assets-report.txt` 與總覽圖 `screenshots/assets-overview.png`（及 -dark／-light）。

**像素規格**（單位：邏輯像素，1 個像素 = 原圖 1 格；每個素材各自取樣，同一隻動物所有姿勢共用同一個取樣比例）：場景邏輯解析度約 480×270（寬度夠時放大 2 倍以上並向左右延伸）；狗站姿高 黃金獵犬 46 ＞ 哈士奇 43 ＞ 邊牧 41 ＞ 柴犬 36 ＞ 貴賓 34 ＞ 柯基 31（柯基寬度仍大）；貓站姿高 布偶 33 ＞ 英短藍貓 32 ＞ 暹羅 31 ＞ 橘虎斑 30 ＞ 三花 29 ≈ 黑貓 28；住家 139×134、鐘樓 123×160、樹 82×103、路燈 51×84；裝飾高 蘑菇 37、樹樁 36、灌木 40、高草叢 38、石頭 34、小花叢 28；狀態與特效圖示統一約 15 高。處理報告有前後尺寸對照表。開發環境有「比例對照圖」（測試模式裡的 📏 按鈕或網址 `?proportions`），把 12 隻動物與住家、樹、鐘樓、路燈用同一個比例並排。動作名稱：狗 stand／walk_a／walk_b／sit_a／sit_b／sleep／eat／happy＋jump／dig_a／dig_b／tug／belly_up／bark；貓 stand／walk_a／walk_b／sit_a／（unused_back：背面，不使用）／sleep／eat／groom＋crouch／pounce／swat／tangled。建築、玩具、玩耍用的素材已處理好放在 manifest 裡，本版畫面上不使用。

**存檔**
- 單一物件（含 `schemaVersion`，目前是 **4**），目前存在 localStorage（鍵名 `aemc-desktop:farm-save`，遊戲最高分沿用舊鍵名，不衝突）。
- 儲存層是 `SaveStorage` 介面（`load`／`save`／`clear`，皆為 Promise），目前實作 `LocalStorageAdapter`，讀寫都包在 try/catch。之後改成帳號綁定的雲端存檔時，只需實作同一介面並呼叫 `setSaveStorage()`。資料格式升級時在 `src/farm/save/migrate.ts` 依 `schemaVersion` 轉換。
- 數值、容量、金幣、價格等調整參數集中在 `src/farm/config/balance.ts` 與 `species.ts`。
- 存檔寫入失敗（瀏覽器空間已滿等）時會顯示提示，不會靜默忽略。舊版存檔讀取時自動升級：v2 以前的海洋生物移除並退還金幣；v3 → v4 新增 `ownedBuildings`（空陣列）、`earning`（賺金幣記錄）、`bowl`（食盆今日份量），寵物、金幣、啟動台清單原樣保留。

**測試模式（只在本機開發環境）**
`npm run dev` 時畫面右下角會有「🧪 測試模式」面板：金幣「加金幣 +10」／+100／+1000、時間快轉 1 小時／1 天、調整寵物各項數值與體重、切換天氣與時段、讓寵物叼禮物、重置養殖場，以及「生物圖鑑」（列出 12 隻動物的所有像素幀）。它透過 `import.meta.env.DEV` 條件式動態載入，正式 build 會被整段移除（`npm run build` 後 `dist/` 內搜尋不到任何測試模式的程式碼）。

**預留給後續階段**：其餘 5 種建築的購買與功能（遊樂設施、營火、野餐墊、花圃、沙坑；v3.3.0，資料與可用性判斷已保留在 `buildingSlots`，本版建築模式不顯示）、「玩耍」互動、拍照、帳號與雲端存檔（金幣經濟目前純前端、無法防作弊）。

## 素材快取（為什麼檔名要帶雜湊）

`public/assets/` 裡的圖集與 manifest 檔名一律帶內容雜湊（`scene.10a965c2.png`、`manifest.18e08371.json`），由 `scripts/process-assets.mjs` 產生，並把目前 manifest 的檔名寫進 `src/farm/pixel/assetIndex.ts`。原因：vite-plugin-pwa 會把 `assets/` 底下所有檔案當成「檔名已帶雜湊」，不會檢查內容有沒有變；沒有雜湊的 `scene.png` 會永遠留在使用者的 service worker 快取裡，新程式就會配到舊圖集。換素材的流程：改素材 → 重跑 `node scripts/process-assets.mjs` → 提交 `public/assets/` 與 `assetIndex.ts`（舊雜湊檔會被自動清掉）。頁面採網路優先、service worker 立刻接手但不自動重新整理，接手時顯示「有新版本，重新整理即可」。

## 金幣經濟（v3.2.0）

純前端、存在瀏覽器，**無法防作弊**（程式註解也有寫；帳號與雲端階段再處理，不加額外機制）。所有數值在 `src/farm/config/balance.ts`，邏輯是純函式（`sim/earning.ts`、`sim/buildings.ts`），時間一律用遊戲時間來源 `gameNow()`（`farm/overrides.ts`；測試模式改時間時跟著變），不用 `Date.now()`；每日進度以**本地日期 00:00** 重置。

- **使用程式**：從啟動台（住家門）點開使用者的程式，成功開啟 +3 金幣；每個程式每小時最多一次、所有程式合計每天最多 +10（最後一次只給剩下的額度）。`window.open` 被擋不給（見下方開啟方式）；管理程式清單（新增、編輯、刪除、恢復預設）不給。給的時候顯示「+3 金幣（今日 3/10）」，啟動台底部也有今日進度。
- **玩遊戲**：遊戲館 5 個遊戲，每局達到各自的達標條件 +1 金幣，所有遊戲合計每天最多 5。遊戲結束時判定一次（2048 沒有明確的結束，所以達到 2048、沒有可移動方塊、或玩到一半重新開始都會判定一次）。達標條件（`BALANCE.gameGoals`）：踩地雷獲勝、2048 最大方塊 512、貪食蛇吃到 10 顆、彈珠台 1500 分、飛機打怪 1500 分。給的時候顯示「+1 金幣（今日 n/5）」，遊戲館視窗顯示「今日遊戲金幣 n/5」。
- **外部程式的開啟方式**：改用 `window.open(url, '_blank')`，成功後立刻把 `opener` 設為 null（`src/lib/openExternal.ts`）。原本的 `'noopener,noreferrer'` 會讓瀏覽器不論成功與否都回傳 null，就分辨不出「被擋」；代價是對方網站的 Referer 會是本站的 origin（瀏覽器預設 strict-origin-when-cross-origin，不含路徑與參數）。
- **存檔**（schema 4）：`ownedBuildings`（已購買的建築 id）、`earning`（`date`、`programCoins`、`gameCoins`、`lastAward` 各程式上次給金幣的時間；冷卻跨日有效，今日進度隨日期歸零）、`bowl`（`date`、`used` 食盆今日已用份量）。

## 建築（v3.2.0 開放三種）

選單列右側「＋領養」旁的「建築」按鈕：進入**建築模式**，草地與走道上顯示本版可購買建築的**虛線空位**（名稱與價格），已購買的不再顯示；再按一次按鈕或按 Esc 離開。點空位彈出小卡片（名稱、價格、一句功能說明、購買），金幣不足時按鈕停用並顯示「金幣不足」；購買成功扣金幣、建築立即出現在該位置並存檔。每個專用空位對應固定一種建築（id 就是專用標記）：

| 建築 | 空位 id | 價格 | 腳下佔地 | 行為 |
|---|---|---|---|---|
| 食盆水盆 | `bowls` | 10 | 48×12 | 飽食度低於 60 且沒在睡覺／洗澡／被操作的寵物自己走去吃（每份 +15 飽食度、不扣金幣），每天 6 份（本地日期 00:00 補滿）、同時最多 2 隻，用完在上方顯示「空」圖示；手動「餵食」仍可用（−1 金幣、+20），兩者並存 |
| 狗窩 | `kennel` | 20 | 76×22 | 睡覺時間（23:00–6:00）最多 2 隻狗睡在座位上：窩裡（只露出頭與 ZZZ）、窩門口（完整躺在窩前），睡座位心情回復 ×2.5；下雨時狗用同樣兩個座位躲雨。窩在路燈後面（左緣被燈桿蓋住） |
| 貓跳台 | `catTree` | 20 | 53×22 | 睡覺時間最多 2 隻貓睡在平台上：頂層圓平台、中層平台（直接出現在平台上，沒有爬上去的動畫），心情回復 ×2.5；下雨時睡著的貓繼續睡，醒著的躲在跳台旁 |

- 其他 5 個空位（遊樂設施、營火、野餐墊、花圃、沙坑）本版不顯示、不開放購買（`PURCHASABLE`），v3.3.0 才做；資料與可用性判斷保留。
- 窄視窗放不下的建築：`buildingAvailability` 判斷，空位不顯示、建築模式顯示「此視窗大小空間不足，請放大視窗」；已購買的建築若在新視窗放不下，購買紀錄保留、畫面上隱藏（也沒有障礙），放大後自動恢復，不退款不刪除。
- 購買後建築的腳下佔地才加入寵物障礙（`slotBlockers(slots, owned)`，`Layout.owned` 記著已購買的 id）；寵物用 A* 尋路繞行（`pixel/nav.ts`），走道下半部至少剩 `PATH_FREE_MIN` = 36（實際 44）。建築依腳底 y 排前後，夜晚一起疊暗色。
- 使用建築的行為在 `pixel/buildingUse.ts`（只決定去哪裡、動作名稱，動作畫面由 `ANIMS` 對應）：每個建築 2 個座位、站在建築前方，從側面或草地來的先走到前方走道再走上座位，不會穿過別的寵物。被叫醒、餵食、撫摸、洗澡、拖曳、選單開著都會放掉座位，之後恢復一般行為；建築坐滿時多出來的寵物用原本的睡覺方式（但周圍太擠會先走到附近不擠的地方再睡）。

## 存檔備份（v3.3.0）

存檔只存在這個瀏覽器的 localStorage，清除網站資料或換瀏覽器就沒了。選單列 Logo →「匯出存檔…」下載一個 JSON 備份檔（養殖場存檔＋啟動台程式清單，含自訂圖示），「匯入存檔…」選檔後會先顯示內容與警告，確認才覆蓋目前的存檔並重新整理網頁。較新版本的存檔、損毀或超過 5 MB 的檔案會被拒絕並說明原因，不會改動任何資料。啟動時會要求瀏覽器「持久儲存」（Logo 選單可看狀態）；從未匯出且寵物滿 3 天、或距上次匯出超過 14 天會跳出不擋操作的小提醒（每天最多一次，可選「不再提醒」）。實作與規則見 CLAUDE.md。

## 拖曳與水池洗澡

- **拖曳寵物**：按住約 150 ms，或移動超過 4 px，開始拖曳；沒拖就是點擊（開氣泡選單）。拖曳中寵物離地約 9 個邏輯像素、開心姿勢、地上留影子。放開：站得住的地方落地彈跳；不可站的地方（住家、鐘樓底座、水池石頭、樹幹、路燈、天空）彈回最近的可走位置；水面上洗澡。睡覺中的寵物也能拖，拖起時醒來（貓心情 −15、狗沒差，不用金幣）。座標轉換全部走 `layout.ts` 的 `fromCss`（處理 devicePixelRatio 與整數縮放）。
- **水池洗澡**（1 點）：落水（水花＋漣漪）→ 泡澡約 4.5 秒（下半身用水面橢圓程式裁切，漣漪、泡泡）→ 爬出到水池前甩水。清潔度 +40、狗心情 +6、貓心情 −3（`config/balance.ts` 的 `BALANCE.bath`）。金幣不足不洗並彈回；同一時間只有一隻，其他的彈回並提示「水池使用中」；洗澡中不能被點、被拖。氣泡選單的「洗澡」會讓寵物自己走到水池前再跳進去，途中點擊或拖曳取消，進水時才扣金幣。
- 程式碼：行為在 `pixel/pets.ts`（`BathState`、`beginBathWalk`、`enterPond`）、拖曳與繪製在 `pixel/engine.ts`、指標手勢在 `farm/index.tsx`。水池位置與水面橢圓在 `pixel/layout.ts`（`pondPos`、`waterEllipse`），要與 manifest 的 `pond_a.meta.water` 一致（測試會比對）。

## 管理程式（啟動台）

外部程式清單是使用者自己的，存在瀏覽器（`aemc-desktop:app-list`，含 `schemaVersion`，透過 `src/lib/documentStorage.ts` 的可替換儲存層，之後可搬到帳號雲端）。

- 新增：啟動台右上角的「＋」→ 填網址（沒寫 http 會自動補 https，只接受 http／https）、名稱、圖示（上傳圖片會置中裁成正方形並縮成 256×256，或使用文字圖示：名稱前 1～2 個字、顏色依名稱雜湊決定）。
- 編輯、刪除：在程式圖示上按右鍵（刪除前會確認）。預設的 5 個程式也可以編輯與刪除。啟動台只放你自己的程式；內建的 5 個小遊戲在鐘塔的「遊戲館」。
- 「恢復預設程式」：還原成預設的 5 個程式。
- 所有外部程式都用新分頁開啟（`window.open`，成功後把 `opener` 設為 null，見「金幣經濟」），所以不需要檢查網站能不能嵌入。

預設的 5 個程式（FilMaster、SpecReader、CheMScutter、EluSim、AutoEllipso）定義在 [src/config/apps.ts](src/config/apps.ts) 的 `DEFAULT_APPS`；圖片圖示放在 `public/icons/`，`icon` 寫 `'icons/檔名.png'`，寫 `''` 則是文字圖示。

## 內建程式與小遊戲

`src/config/builtinApps.ts` 用來登錄「內建程式」：直接在桌面視窗中渲染 React 元件。元件會收到 `active`（是否為作用中視窗）與 `minimized`（是否最小化）兩個屬性。`category: 'games'` 的程式是小遊戲，只列在「遊戲館」視窗（`components/GameHall.tsx`，鐘塔的門開啟），不在啟動台；開啟時才出現在 Dock。

目前的 5 個遊戲（程式碼在 `src/games/<遊戲名稱>/`，共用的暫停、結算畫面、音效、縮放畫布在 `src/games/shared/`）：

| 遊戲 | 資料夾 | 操作 |
| --- | --- | --- |
| 踩地雷 | `minesweeper` | 初級 9×9、中級 16×16、高級 30×16；左鍵翻開、右鍵插旗、點數字快速翻開。最高紀錄是各難度的最短時間 |
| 2048 | `game2048` | 方向鍵或 WASD |
| 貪食蛇 | `snake` | 方向鍵或 WASD；分數越高速度越快 |
| 彈珠台 | `pinball` | Z／← 左擋板、/／→ 右擋板；按住空白鍵蓄力、放開發射；也可以點畫面左半邊或右半邊控制擋板、用「發射」按鈕蓄力。物理使用 matter-js，3 顆球 |
| 飛機打怪 | `shooter` | 自動射擊；方向鍵、WASD 或拖曳移動。每 5 波一隻 Boss；P 火力升級（最高 5 級）、S 護盾 |

共通行為：

- 全部用 Canvas 或 React 繪製，沒有外部圖片；畫面隨視窗大小縮放。
- 有開始畫面、暫停（P 或 Esc）、遊戲結束畫面。視窗最小化、不是作用中視窗、分頁隱藏或瀏覽器失去焦點時會自動暫停。
- 最高分存在 localStorage（鍵名 `aemc-desktop:<遊戲>:best`），讀寫都有 try/catch，無痕模式也不會出錯。
- 音效用 WebAudio 合成，預設關閉，視窗右上角的喇叭按鈕可開關。

新增遊戲的做法：在 `src/games/<名稱>/index.tsx` 寫一個接收 `BuiltinAppProps` 的元件（可用 `useGameStatus` 與 `GameShell`），再到 `builtinApps.ts` 登錄。

## 部署到 GitHub Pages

1. 把專案推送到 GitHub（repo 名稱 `AEMC-lab-desktop`）。
2. 到 repo 的 **Settings → Pages**，**Source** 選 **GitHub Actions**。
3. push 到 `main` 分支後，[.github/workflows/deploy.yml](.github/workflows/deploy.yml) 會自動 build 並部署。
4. 部署完成後網址為 `https://<帳號>.github.io/<repo 名稱>/`。

Vite 的 `base` 讀取環境變數 `BASE_PATH`；Actions 會自動帶入 `/<repo 名稱>/`，本機開發則為 `/`。若要改用其他 repo 名稱，不需要修改程式。

## 版本管理

每次修改程式都要更新 `package.json` 的 version 與 [CHANGELOG.md](CHANGELOG.md)，並 commit、打 tag，詳見 [CLAUDE.md](CLAUDE.md)。「關於這個桌面」顯示的版本號與更新日期，是建置時分別從 `package.json` 與 CHANGELOG 最上方的紀錄讀取。
